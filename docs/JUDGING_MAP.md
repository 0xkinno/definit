# Judging map

This document maps each criterion to the artifact that demonstrates it, so the
evidence can be checked rather than taken on trust. Every path below exists in
a clean checkout, and every number below is produced by a command.

## Criteria

### 1. Does it build on the sponsor's primitive rather than around it?

The product is a consequence of one sponsor property: a GenLayer decision is
readable in more than one storage scope, and the scopes disagree while a
decision is still appealable.

- Mechanism written up in `docs/DISCOVERY.md`.
- The pinned surface, including the exact runner and the storage-scope
  enumeration, is recorded in `docs/ARCHITECTURE.md` and
  `artifacts/deployment.json`.
- The rule the vault enforces is asserted on chain: `DecisionGate.describe()`
  and `FinalityVault.describe()` both return
  `capability_read_scope: FINALIZED_CAPABILITY`, `finality_rule:
  promoted-plus-appeal-window` and the same `appeal_window_seconds`. All three
  are read back by `npm run verify`, and `tests/attacks/test_guards.py` fails if
  the two contracts ever disagree about the window.

### 2. Is the problem real, and stated precisely?

- One-line statement of the defect and the invariant: `docs/DISCOVERY.md`.
- The invariant is written as a single predicate over five inputs and is
  restated in the README under *The Hard Invariant*.
- The failure it prevents is demonstrated, not asserted: case
  `accepted-not-final` in `tests/fixtures/cases.json` releases value against an
  appealable decision in the baseline arm and is refused in the intervention arm.

### 3. Is there a working end-to-end implementation?

- Three contracts, all compiled against the live network's own schema endpoint
  by `npm run contracts:check`.
- Addresses and transaction hashes: `artifacts/deployment.json`.
- Full seven-step lifecycle with real transaction hashes:
  `artifacts/live-lifecycle.json` and `docs/EVIDENCE.md`.
- Reproduce with `npm run deploy && npm run seed && npm run lifecycle`.

### 4. Is the claim proven, and is the proof honest?

- Corpus: `tests/fixtures/cases.json` (twelve cases, nine refusals, three
  acceptances).
- Runner: `tests/attacks/`.
- Report: `docs/evidence/proof-report.json`, generated by `npm run proof`.
- Baseline and control arms are separate contracts, described in
  `docs/PROOF.md`.
- Anything not proven is listed in `docs/LIMITATIONS.md`, including the
  falsifiers that would overturn the claim.

### 5. Is the product usable by a person?

- Landing page explains the defect and the boundary in plain language.
- Protection console at `/console` runs the lifecycle and shows both sides of
  the boundary for the same decision.
- Read-only action inspector at `/actions/[id]` and a printable settlement
  receipt at `/receipts/[id]`.
- Proof lab at `/lab` runs the corpus and displays per-case results.
- Evidence page at `/proof` renders the generated report.
- Accessibility and layout are checked at eight viewports by the Playwright
  suite in `tests/e2e/`, including a 320px floor and a 44px minimum target
  size.

### 6. Is it reproducible?

- `npm install`, copy `.env.example` to `.env.local`, fill the operator key.
- `npm run contracts:check` compiles every contract against the live schema
  endpoint.
- `npm run deploy`, `npm run seed`, `npm run lifecycle`.
- `npm run proof && npm run evidence && npm run verify:submission`.
- The full list, in order, is in `docs/EVIDENCE.md` under *Reproducing*.

### 7. Is the submission clean of survey material?

- `npm run audit:isolation` walks every shipped file and fails if any word from
  the survey vocabulary, or any surveyed project name, appears outside
  `research/`.
- The result is written to `docs/evidence/isolation-audit.json`.
- `research/` is listed in `.gitignore` and is never part of the submission.

### 8. Does the documentation set close?

- `npm run docs:check` asserts that every required document exists, contains
  its promised sections, and that every relative link resolves to a real file.
